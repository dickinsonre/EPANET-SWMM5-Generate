# Grade & Review: EPANET 2.3 / SWMM 5.2.4 Network Generator

## Overall Grade: **A− (90/100)**

This is an impressively ambitious tool — a single-file, ~160 KB HTML app that generates hydraulically valid EPANET and SWMM models from 50 to 100,000 nodes, complete with procedural city backdrops, calibration features, and an embedded WASM solver. For a free educational/research tool, it punches well above its weight.

---

## Category Grades

| Category | Grade | Notes |
|---|---|---|
| **Scope & Ambition** | A+ | EPANET + SWMM in one tool; 50–100K node range; both US/SI units |
| **Hydraulic Validity** | A | BFS connectivity check, critical-path pump sizing, pressure zone auto-detection, 3-point pump curves |
| **Realism of Patterns** | A | Spatially clustered demand zones, age-correlated C-factors, Weibull RDII degradation curves |
| **SWMM Feature Depth** | A+ | 10 conduit shapes, 7 LID types, 8 pollutants, RDII with proper statistical distributions, snowmelt, groundwater |
| **Reproducibility** | A+ | Mulberry32 seeded PRNG — strong scientific practice |

| **UX / Discoverability** | B− | Massive control panel; could overwhelm new users |
| **Validation / QA** | B | Stats are shown, but a **0.50 S/D ratio "DEFICIT"** appearing in the default generation is a red flag |
| **Export Ecosystem** | A | .inp, GeoJSON, DEM (.asc), PNG, .dat calibration files, batch ZIP |
| **Offline / Portability** | A+ | Single HTML file, no install, no server, no dependencies |

---

## What's Genuinely Excellent

1. **The "truth model" calibration pedagogy.** Generate → corrupt C-factors → calibrate back → measure RMSE. This is the right way to teach calibration, and very few tools support it natively.
2. **RDII statistical rigor.** Weibull degradation for R-values, log-normal for K, Beta(2,5) for sewer area, T scaled by √(Area/slope) — this is far beyond the uniform-random sampling most generators use.
3. **Hydraulically-aware topology.** Pumps/valves inserted by splitting pipes (not parallel links), PRVs at auto-detected elevation zone boundaries, reservoirs replacing junctions rather than floating.
4. **The Tom Walski eyewitness piece** about Lew Rossman's 1991 workshop — genuine institutional memory you don't see on tool websites.

---

## Issues & Suggestions for Improvement

### 🔴 High Priority

1. **Default generation produces a supply deficit (S/D = 0.50).** The example log shows "DEFICIENT — 5807 GPM supply vs 11614 GPM peak demand" out of the box. This will confuse beginners who don't yet know to read the Stats tab. **Suggestion:** Either auto-size reservoir heads/pump capacity to hit S/D ≥ 1.1 by default, or flash a prominent warning banner with a one-click "Auto-balance supply" button.

2. **Connectivity says "99% of 1069 nodes reachable" with "0 isolated"** — that math doesn't reconcile. 1% of 1069 ≈ 11 nodes. **Suggestion:** Either fix the rounding/display or expose the actual unreachable count alongside the percentage.

3. **No mention of validation against published benchmark networks** (e.g., Net1, Net2, Net3, BWFLnet, C-Town, KY series). **Suggestion:** Add a "Reproduce Net3" or "C-Town-like" preset so users can compare generated models against canonical literature networks.

### 🟡 Medium Priority

4. **The control panel is overwhelming.** I count 25+ collapsible sections with hundreds of parameters. **Suggestion:** Add a "Simple / Advanced / Expert" mode toggle that hides 80% of controls for new users. The presets help, but each preset still exposes everything.

5. **No sensitivity/uncertainty analysis hooks.** Given the calibration focus, this is a missed opportunity. **Suggestion:** Add Monte Carlo perturbation — "generate 50 variants with C-factors ±10%, demands ±15%" as a ZIP. This would dovetail beautifully with WNTR workflows.

6. **No EPANET-MSX export.** With 8 SWMM pollutants supported, the absence of multi-species WQ on the EPANET side feels asymmetric. **Suggestion:** Add basic MSX export (chlorine + THM precursor + bromate, or chloramine decay).

7. **Pump curve generation uses only 3 points.** EPANET accepts more, and real pumps have characteristic non-linear curves. **Suggestion:** Optionally generate 5–7 point curves with realistic BEP placement, plus efficiency curves wired to the [ENERGY] section.

8. **DWF / RDII / Direct Inflows are SWMM-only.** EPANET 2.2+ supports time-varying patterns that could simulate similar effects. **Suggestion:** Even simple "leak growth over simulation" via emitters would expand the EPANET pedagogical scope.

### 🟢 Polish / Nice-to-Have

9. **Add a "Validate INP" button** that round-trips through the WASM solver and reports warnings/errors inline before download. The "Run Solver" button is there but separating *generation* from *validation* would be clearer.

10. **GeoJSON could include CRS metadata.** Currently coordinates appear to be in arbitrary planar units. Adding a fake EPSG (e.g., a local state plane) would make QGIS imports more useful.

11. **Add a "Diff two models" view** for the truth-vs-calibrated workflow. Show pressure deltas, flow deltas, RMSE heatmaps directly in-browser.

12. **Snowmelt and groundwater toggles should expose calibration-relevant defaults** (current defaults are buried and uncommented in the INP).

13. **Mobile UX claim ("Mobile-optimized, 44px touch targets")** is admirable, but generating a 100K-node model on a phone seems aspirational. **Suggestion:** Auto-cap preset selection by device memory.

14. **Citations could be tighter.** The Vallabhaneni et al. (2007) SSOAP reference is appropriate, but the RDII Weibull anchor points ("R≈0.01 at 5 yr, 0.10 at 60 yr") would benefit from explicit source citations rather than "empirical patterns from RDII calibration studies."

15. **License clarity.** "Free for education and testing" — is this MIT/BSD/CC-BY? Researchers need to know before citing in published work.

---

## Comparison Context

Against the alternatives:
- **vs. Classic EPANET**: This tool *generates*, EPANET *analyzes* — complementary, not competing.
- **vs. epanet-js**: Better for synthetic model creation; epanet-js better for editing real models with satellite tiles.
- **vs. WaterGEMS/InfoWater**: Obviously can't match commercial GIS/optimization depth, but for *teaching* and *algorithm benchmarking* it's arguably better-suited.
- **vs. KY/BWFL/L-TOWN benchmark networks**: Those are fixed; this is parametric. Different use cases.

There's genuinely no other free tool that does parametric, calibration-ready, EPANET+SWMM model generation at this scale in a browser.

---

## Bottom Line

A strong A-minus. The hydraulic reasoning is sound, the documentation is professorial, and the SWMM RDII statistical work is publication-worthy. The main things keeping it from an A+ are (1) the out-of-the-box supply deficit that needs fixing, (2) the overwhelming UI for newcomers, and (3) the missed opportunity for built-in sensitivity/uncertainty workflows that would make it indispensable for graduate hydraulic modeling courses.

If the author addresses items 1, 4, and 5 above, this becomes the de facto teaching tool for water distribution and stormwater modeling courses worldwide.
