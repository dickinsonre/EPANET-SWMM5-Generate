Understanding the Generated Model
The generator applies real engineering logic, not pure randomness:

Connectivity validation (BFS): A breadth-first search from every source confirms each junction is reachable; isolated nodes are counted and reported.
Pump sizing via critical path: BFS traces the hydraulically farthest node, computes Hazen-Williams friction along that path, and builds a 3-point pump curve that brackets the operating point (the AWWA-recommended approach).
Pressure-zone detection: If the elevation range exceeds ~80 ft, the network is split into ~70 ft zones with PRVs at the boundaries.
Spatial realism: C-factors correlate with location (downtown = older/rougher, suburbs = newer/smoother); pipe ages trend from 1950s near the center to 2020s at the edges; demand zones cluster (industrial, commercial, residential).
Flow-based pipe sizing: Diameters are chosen from estimated flows toward a 2–5 ft/s target velocity (min 6" distribution / 12" arterial).
Street-routing factor: Pipe lengths are multiplied by a density-scaled factor to approximate routing along streets rather than straight lines — ~1.55× in the dense, older urban core (irregular older grid) tapering to ~1.15× at the newer suburban edges.
For SWMM, subcatchments use a D8 flow-direction algorithm for drainage routing, and RDII uses statistically rigorous RTK distributions.

Calibration Workflow (Truth → Corrupt → Recover)
This tool is built for the classic calibration teaching pattern:

Generate a "truth" model. Lock the seed so it's reproducible. Run the solver to get "true" pressures/flows. Export a calibration file (.cal / .dat) — these become your field observations.
Create a "corrupted" model. Change the seed or manually degrade parameters (e.g., set all C-factors to a wrong guess like 100, or scale demands). This is the model a student starts from, not knowing the truth.
Calibrate back. Adjust roughness, demands, and statuses until the corrupted model's results match the observed calibration file. Compare against the truth to grade the recovery.
Automated Calibration Scoring (in-app). The Results tab now closes this loop without leaving the browser:

Run the solver on your truth model (use the ▶ Run Solver button right on the Results tab — it auto-loads the WASM engine if needed).

Click 📌 Save as Truth to snapshot the truth results (mode, seed, units are recorded).

Corrupt or recalibrate the model (change C-factors, demands, seed, etc.) and re-run the solver.

Click 🎯 Score vs Truth. The tool computes RMSE for pressure (or node depth in SWMM), flow, and demand across every shared element and timestep, then assigns a letter grade against AWWA M32 pressure targets (note: in AWWA M32 a higher calibration level means a stricter tolerance, so Level 3 is tighter than Level 1):

10.1 Node-count sweep (many models across a size range)
Where the Monte Carlo ensemble (§10) varies parameters while the topology stays fixed, the node-count sweep does the opposite: it varies the model size itself and holds every other setting constant. One click produces a whole series of models that grow from a small network to a large one in regular steps — ideal when you need a graduated family of .inp files rather than a single model.

Where to find it
Generate any network first (EPANET or SWMM), then open Map & Export. Below the Batch ZIP controls you'll see the 📈 Node-Count Sweep panel with three numeric fields and a Generate Node Sweep ZIP button. The panel is mode-aware: in EPANET mode it emits EPANET 2.3 models, in SWMM mode it emits SWMM 5.2.4 models — no other switch required.

The three inputs
Field Meaning Rules
Min Smallest target node count (the first model) Must be ≥ 9 (a 3×3 grid)
Max Largest target node count (the last model) Must be ≥ Min
Step Node-count increment between successive models Must be ≥ 1
The tool generates one model for every target value in the inclusive series Min, Min+Step, Min+2·Step, … up to (and including, when it lands exactly) Max. The number of models produced is therefore floor((Max − Min) / Step) + 1.

Example: Min = 50, Max = 1000, Step = 50 → 20 models targeting 50, 100, 150, … , 1000 nodes. Min = 100, Max = 10 000, Step = 100 → 100 models. Min = 9, Max = 99 856, Step = 1 → the maximum-resolution sweep.

How a target becomes a model (the grid mapping)
Each target node count T is converted to a near-square grid:

dim = round( sqrt(T) ) # clamped to the 3 … 316 range
rows = dim
cols = dim

So a target of 1000 → round(√1000)=32 → a 32×32 grid (≈1024 junctions before sources are added). Every other setting — spacing, reservoirs, tanks, pumps, valves, terrain, demand model, storm, units, theme — is taken exactly as you have it configured in the sidebar. The sweep only rewrites gridRows/gridCols; it restores your original grid values when it finishes, so your on-screen model is untouched.

Because the grid must be square-ish and integer-dimensioned, the realized node count is quantized. Targets that round to the same dim produce the same grid (and thus the same actual size). The band that maps to a given dim is (dim−0.5)² ≤ T < (dim+0.5)²; for dim = 32 that is 993 … 1056 inclusive (since √1056 ≈ 32.496 still rounds to 32, while √1057 ≈ 32.512 rounds to 33). So with Step = 1, the 57 targets 1000–1056 all collapse onto the same 32×32 grid. This is expected: the sweep guarantees a model for every requested step, but the actual sizes advance in discrete jumps. Use a Step of roughly 2·dim+1 (the spacing between consecutive perfect squares near your range) if you want every model to be a distinct size.

Reproducibility — one seed for the whole series
Every model in the sweep uses the same seed (whatever is in the Seed box when you click Generate). That is deliberate: with the seed and all parameters held constant, the only variable across the set is the network size, which is exactly what you want for a clean scaling study. Re-running the sweep with the same seed and inputs reproduces byte-identical .inp files. (If you instead want size and randomness to vary, run several sweeps with different seeds, or use Batch ZIP for same-size/different-seed sets.)

What you get — ZIP contents
A small/medium sweep downloads as a single <mode>node_sweep<N>models.zip (e.g. epanet_node_sweep_20models.zip). Large sweeps are streamed as multiple ZIP parts — see Limits & performance below — named <mode>node_sweep_part01<count>models.zip, …part02…, and so on; each part is a fully self-contained ZIP. Either way, every ZIP contains:

One .inp per step, named:

EPANET23_<NNN>target<T><dim>x<dim><actual>nodes_seed<seed>.inp SWMM524<NNN>target<T><dim>x<dim>_<actual>nodes_seed<seed>.inp

where <NNN> is a zero-padded sweep index (001, 002, …), <T> the requested target, <dim>×<dim> the grid, and <actual> the realized node count. The index prefix guarantees filenames are unique even when several targets round to the same grid — nothing overwrites anything inside the ZIP.

Limits & performance
Model count cap: 100,000 models per run. If your Min/Max/Step would exceed this, the tool refuses and asks you to widen the Step or narrow the range.
Size cap: ≈99,856 nodes per model (the 316×316 grid ceiling).
Models are generated sequentially in the browser, yielding to the UI between each so the tab stays responsive and shows live i / N (and · part P) progress on the button.
Memory-safe multi-part streaming. To keep memory bounded on big runs, the tool does not hold the whole sweep in memory. Instead it accumulates models into a part and flushes that part to a downloaded ZIP — then frees the memory — once the part reaches ~64 MB of .inp text or 1000 models, whichever comes first. So a run is delivered as one ZIP when it's small, or as several numbered parts (…_part01…, …_part02…) when it's large. This is why a very large sweep produces multiple downloads. (Earlier builds buffered everything and could exhaust tab memory on large sweeps — this streaming approach fixes that.)
Allow multiple downloads. Because parts download automatically as they complete, your browser may prompt to "allow multiple file downloads" on the first large run — accept it, or the later parts will be blocked.
Practical runtime scales with both the number of models and their sizes — a few dozen small models finish in seconds, whereas thousands of large (10k+ node) models can still take many minutes (memory is bounded, but CPU time is not). For the fastest big runs, prefer smaller per-model sizes.

Hydraulics Cheat Sheet
Hazen-Williams head loss (US units):

h_f = 4.73 · L · (Q / C)^1.852 / D^4.87 (h_f in ft, L in ft, Q in cfs, D in ft)

C = roughness coefficient (higher = smoother). New PVC ≈ 150; old cast iron ≈ 80.
Valid for water at 40–75 °F, turbulent flow (Re > 4000). Empirical, not physics-derived, but standard US practice because C-factors are well documented.
Pressure ↔ head (US units):

pressure (psi) = 0.433 · head (ft) head (ft) = 2.31 · pressure (psi)

Rules of thumb:

Quantity Healthy range
Service pressure 40–80 psi (min ~20 psi under fire flow)
Pipe velocity 2–5 ft/s (peak)
S/D ratio ≥ 1.1–1.2
Fire flow 500–3,500+ gpm depending on land use
Valve types: PRV (limits downstream P), PSV (maintains upstream P), PBV (fixed P drop), FCV (limits flow), TCV (throttle), GPV (custom head-loss curve).

Glossary
BFS — Breadth-First Search; used to verify every node connects to a source.
C-factor — Hazen-Williams roughness coefficient (higher = smoother pipe).
Demand — Water draw at a junction (gpm or L/s).
Emitter — A pressure-dependent outflow (models leaks or hydrants).
HGL — Hydraulic Grade Line; elevation of the energy/pressure surface.
Peaking factor — Ratio of peak-hour to average demand (default 1.6; design mode 2.0).
PRV — Pressure-Reducing Valve; common at pressure-zone boundaries.
RDII — Rainfall-Derived Infiltration and Inflow (SWMM sewers).
RTK — Three-parameter unit-hydrograph method for RDII.
S/D ratio — Supply capacity ÷ peak demand. < 1.0 = deficit.
Seed — Number that makes a generated network reproducible.
Subcatchment — A drainage area in SWMM that routes runoff to a node.

Classroom Exercises
A. First Network (15 min) Generate a Tiny (50) EPANET model. On the Map tab, click a junction and a pipe to read their properties. Identify the reservoir and trace a path from it to a dead end.

B. Diagnose a Deficit (20 min) Lower the reservoir head until the health summary turns red (S/D < 1.0). Then fix it two ways: (1) raise reservoir head, (2) add a pump. Compare the resulting S/D ratios.

C. Pressure Zones (20 min) Increase the elevation range above 80 ft and regenerate. Find the auto-created pressure zones and the PRVs at their boundaries (Stats + Map).

D. Calibration (45 min) Follow §9: generate a locked-seed truth model, export its calibration file, corrupt the C-factors, then recover them. Grade your recovery against the truth.

E. Uncertainty (45 min) Export a 50-member Monte Carlo ensemble (§10). Solve all members in WNTR and plot the distribution of minimum pressure across the ensemble.
