# App Review: EPANET 2.3 & SWMM 5.2.4 Network Generator

**URL:** https://epanet-swmm-5-generate.replit.app/

---

## Overall Grade: **A-** (91/100)

This is a remarkably ambitious and well-executed single-file web application. Here's the breakdown:

---

## Category Grades

### 1. Feature Set & Scope — **A+** (97/100)

This is where the app truly shines. It's arguably the most feature-rich free hydraulic model generator available anywhere.

**Strengths:**
- Covers both EPANET *and* SWMM in one tool — no other free tool does this
- 50 to 100,000 nodes — the range is extraordinary for a browser-based tool
- Complete SWMM environmental modeling: RDII with statistically rigorous RTK distributions (Weibull degradation curves, log-normal sampling), 7 LID types with full multi-layer definitions, snowmelt, groundwater, design storms, 8 water quality pollutants
- EPANET features rival commercial tools: emitter nodes, chlorine WQ, secondary demands, pipe tagging, pressure zone auto-detection, pump critical-path sizing
- Seeded PRNG (Mulberry32) for reproducibility — critical for research and calibration exercises
- GeoJSON, DEM, and calibration file exports — extremely useful for GIS integration
- Monte Carlo ensemble generation for uncertainty analysis

**Minor gaps:**
- No SCADA data import or comparison workflow built in
- No multi-species water quality (though this is niche — EPANET-MSX territory)
- No transient analysis acknowledgment/warning beyond the documentation

---

### 2. Technical Quality & Hydraulics — **A** (93/100)

The engineering logic is impressively sound for a generator.

**Strengths:**
- Connectivity validation via BFS — every junction confirmed reachable, isolated node count displayed
- Pump sizing uses critical-path Hazen-Williams friction analysis with 3-point curves bracketing the operating point — this is the correct approach per AWWA guidelines
- Pressure zone auto-detection when elevation range exceeds 80 ft, with PRVs at boundaries
- C-factors spatially correlated with position (downtown = old/rough, suburban = new/smooth) — realistic
- Pipe ages correlated with distance from center (1950s→2020s)
- RDII RTK parameters based on empirical degradation models, not uniform random — the Weibull curve R(age) = R_new + (R_max − R_new) × (1 − e^(-(age/τ)^n)) is scientifically defensible
- Supply-demand balance check with S/D ratio displayed
- Flow-based pipe sizing with iterative H-W correction

**Concerns:**
- The S/D ratio shown in the example is **0.50 (DEFICIENT)** — this means the generated model has a supply deficit out of the box. For a teaching/calibration tool, a model that immediately shows "DEFICIT" could confuse beginners. The generator should either auto-adjust supply to meet demand or clearly warn/explain why this is intentional
- Booster pump sizing sometimes shows "0 ft elevation change" (e.g., PU8) — why is a pump needed with zero elevation differential? This should be explained or avoided
- The "1.3× street-routing factor" for pipe lengths is a reasonable approximation but undocumented in most literature. A citation or justification would help

---

### 3. User Interface & Usability — **B+** (87/100)

**Strengths:**
- Clean, well-organized panel structure with collapsible sections
- Quick presets (Tiny through City) reduce configuration friction
- 44px touch targets and mobile optimization — thoughtful for field use
- Copy-to-clipboard for INP text
- Multiple export formats in one click
- Real-time stats panel showing node/link counts, demand totals, connectivity
- Visual preview with elevation heatmap, demand zones, Voronoi polygons
- City map backdrop with three styles (Light, Satellite, Blueprint)

**Weaknesses:**
- The interface is **overwhelming for beginners**. There are dozens of parameters visible simultaneously — from RDII RTK coefficients to snowmelt dividing temperature. A "Simple Mode" vs "Advanced Mode" toggle would help
- No tooltips or help text visible for most parameters. What does "ATI Weight" mean? What's a reasonable "Emitter Node" count? New users will be lost
- No undo/redo for configuration changes
- The "Load WASM Engine ▶ Run Solver" button is somewhat hidden and its purpose isn't immediately clear
- No progress indicator during generation for large models (50K+ nodes could take several seconds)
- The Quick Sim (Pressure Map) feature requires loading a WASM engine — this extra step isn't obvious

---

### 4. Documentation & Education — **A** (95/100)

This is one of the app's greatest strengths. The embedded documentation is extraordinary.

**Strengths:**
- Complete "EPANET Fundamentals Reference" covering hydraulics from first principles
- Detailed explanation of the Global Gradient Algorithm
- C-factor reference table by material and age
- Demand modeling patterns with actual multiplier values
- Pump curve requirements and affinity laws
- Calibration practice exercises with actual Python/WNTR code
- Feature comparison table against commercial tools
- Head loss formula reference with roughness heights
- Fire flow analysis guidance
- Tom Walski's eyewitness account of EPANET's origin — wonderful historical context

**Weaknesses:**
- The documentation is buried inside the app — it's not linked from any obvious "Help" or "Learn" button
- No in-app tutorial or guided walkthrough for first-time users
- The calibration exercises reference specific model sizes but don't provide pre-generated examples

---

### 5. Code Quality & Architecture — **A-** (90/100)

**Strengths:**
- Single HTML file, ~160 KB, zero dependencies — remarkable engineering
- Fully client-side, no server required, works offline
- Runs in Chrome, Firefox, Safari, Edge (WebAssembly + Canvas API)
- Reproducible outputs via seeded PRNG
- WASM-compiled EPANET 2.3 and SWMM 5.2.4 solvers for in-browser simulation

**Concerns:**
- Single-file architecture at 160 KB means there's a LOT of JavaScript in one file. This makes maintenance and contributions difficult. A modular build process with a single-file output would be more sustainable
- No visible version number or changelog
- No automated tests mentioned
- Error handling for edge cases (e.g., what happens with 100K nodes on a mobile device with 2GB RAM?)

---

### 6. Output Quality & Compatibility — **A** (94/100)

**Strengths:**
- .inp files load directly into EPANET 2.2+, EPA SWMM 5.2+, WNTR, PySWMM, InfoWorks ICM, WaterGEMS, PCSWMM
- Title block documents all generation assumptions — excellent for reproducibility
- INP keyword coverage is comprehensive (35+ EPANET sections, 40+ SWMM sections)
- GeoJSON export for GIS integration
- DEM (ASCII grid) export with IDW-interpolated elevation — compatible with ArcGIS/QGIS
- Map PNG export at 2400×1600 at 2× DPI

**Minor issues:**
- The example INP shows 7,642 lines omitted — hard to verify completeness
- No validation report export (mentioned in the feature table but not clearly accessible)
- The calibration .dat file format isn't documented in the search results

---

### 7. Research & Calibration Utility — **A** (93/100)

**Strengths:**
- "Truth model + corrupted model" workflow for calibration exercises is excellent pedagogical design
- Monte Carlo ensemble generation (fixed topology, perturbed parameters) for uncertainty quantification
- Configurable calibration features: emitters, WQ, secondary demands, tags
- Three progressive calibration exercises (manual, automated, demand pattern) with working Python code
- Supply-demand balance check helps identify modeling issues immediately

**Weaknesses:**
- No built-in "calibration score" or automated comparison between truth and corrupted models
- The Monte Carlo feature only perturbs C, Q, and Z — adding demand multiplier and pump curve perturbations would be valuable
- No batch scenario export (run N scenarios, export all)

---

## Detailed Suggestions for Improvement

### High Priority

1. **Fix the Default S/D Ratio** — A newly generated model showing "0.50 DEFICIT" is problematic for teaching. Either:
   - Auto-scale reservoir heads or pump capacity to achieve S/D ≥ 1.2
   - Add a prominent "Why is my model deficient?" tooltip explaining supply vs. peak demand
   - Include a "Fix Supply" button that adjusts sources to balance

2. **Add a Beginner/Advanced Mode Toggle** — Collapse the 40+ configuration panels into a "Quick Start" view showing only: Preset, Units, Duration, and Generate. Show everything else in "Advanced" mode.

3. **Add Inline Tooltips** — Every parameter should have a hover tooltip explaining what it does and what a reasonable range is. For example:
   - "ATI Weight: Antecedent Temperature Index weight (0–1). Higher = more influence of recent temperature on snowmelt. Typical: 0.5"
   - "Emitter Nodes: Number of junctions with pressure-dependent leakage emitters. Typical: 5–15% of nodes."

4. **Add a "Walkthrough" Tutorial** — A step-by-step guided mode that generates a small model, explains each component, and teaches basic EPANET concepts.

### Medium Priority

5. **Explain Pump Placement Edge Cases** — When a booster pump shows "0 ft elevation change," either skip it or explain that it's providing head for downstream friction losses.

6. **Add Model Validation Report** — Export a summary of connectivity, supply-demand balance, pressure range, velocity range, and potential issues (negative pressures, high velocities) as a standalone text or PDF report.

7. **Improve Large-Model Performance Feedback** — Add a progress bar or generation log for models >10K nodes. Show estimated generation time.

8. **Add Demand Multiplier Perturbation to Monte Carlo** — Currently only C, Q, and Z are perturbed. Adding demand uncertainty (±10–20%) would make ensembles more realistic.

9. **Create a "Share Configuration" Feature** — The "Copy Config" button exists, but a shareable URL with encoded settings would be powerful for collaboration and bug reporting.

10. **Add Keyboard Shortcuts** — Generate (Ctrl+Enter), Download (Ctrl+S), Copy INP (Ctrl+Shift+C), Toggle Map (Ctrl+M).

### Low Priority

11. **Add Dark Mode** — The satellite map style exists, but the control panels don't have a dark theme.

12. **Add a "Compare Models" View** — Side-by-side stats for two generated models to facilitate calibration exercises.

13. **Add SWMM/EPANET Hybrid Mode** — Generate a coupled model where the EPANET water distribution network feeds the SWMM sanitary sewer system (for combined sewer overflow analysis).

14. **Add Plugin/Extension Architecture** — Allow users to add custom demand patterns, pipe materials, or LID types.

15. **Publish to npm/PyPI** — Package the generator as a Node.js or Python module for programmatic model generation in research pipelines.

## Final Verdict

This is an **exceptionally well-built educational and research tool** that punches far above its weight class. A single ~160 KB HTML file that generates hydraulically valid EPANET and SWMM models up to 100,000 nodes — with city maps, calibration features, Monte Carlo ensembles, and WASM solvers — is a genuinely impressive engineering achievement.

The documentation alone (covering everything from the Global Gradient Algorithm to Tom Walski's eyewitness account of EPANET's origin) makes this worth bookmarking as a reference, independent of the generator itself.

The main areas for improvement are **discoverability** (beginners will be overwhelmed) and **feedback** (the deficient S/D ratio, pump edge cases). With a beginner mode, inline help, and a tutorial walkthrough, this could easily be an A+ tool.

For anyone teaching hydraulic modeling, running calibration exercises, stress-testing solvers, or needing quick test networks for research — this is now the go-to tool. The comparison to WaterGEMS ($5,000+/year) is not hyperbolic; for generation and calibration practice, this free tool genuinely competes.
